## 진단 변천사

1. **첫 가설** (issue_koalpaca_Q.md): 양자화 스킴 mismatch (NF4↔K-quants).
   → Path A로 NF4 정확히 재현해도 실패 → **부분 기각**.

2. **두 번째 가설** (path-a-results.md v1): LoRA 학습 부족 (epoch=0.39, loss=2.53).
   → 그런데 모델 공식 F-1 = 60.94%. 학습 환경에선 작동했다는 증거.
   → 재학습으로 해결되는 문제 아니라는 게 advisor와 후속 실험에서 확인됨.

3. **세 번째 가설**: 1070 Ti VRAM 부족 → CPU offload가 LoRA 효과 손실.
   → llama.cpp Q4_K_M (전부 GPU, CPU offload 없음)도 in-distribution에서 동일 실패.
   → **부분 기각**.

4. **최종 진단**: **LoRA가 학습 시점 forward 경로에 sharp-tuned, 모든 환경 변화에 fragile.**
   다음 5가지 중 하나라도 바뀌면 효과 소실:
   - 양자화 알고리즘 (NF4 ↔ K-quants)
   - compute_dtype (bf16 → fp16)
   - device placement (전부 GPU → CPU offload 일부)
   - weight 적용 방식 (PEFT attach ↔ pre-merge)
   - transformers/peft 라이브러리 버전

   학습 환경(Colab A100 40GB · NF4+bf16 · 전부 GPU · PEFT attach · Dec 2024 git head)을 1070 Ti에서 100% 재현 불가능.

## 부수 발견

- **transformers 5.x는 Windows에서 12.8B sharded safetensors 로드 시 access violation으로 세그폴트** (`torch/storage.py:456`). 4.x로 다운그레이드 필요.
- **peft 0.12는 어댑터의 `eva_config` 필드 모름** → 0.14 이상 필요.
- **GPT-NeoX tokenizer가 `token_type_ids` 반환** → `generate()` 거부, pop 필요.
- **bitsandbytes NF4 + CPU offload는 `llm_int8_enable_fp32_cpu_offload=True` 명시 필요** (명세서 누락).
- **C: 드라이브 4.3GB만 남아 pip/HF 캐시 E:로 우회 필요** (디스크 공간 함정).

## 남은 의미
