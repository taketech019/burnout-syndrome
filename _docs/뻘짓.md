## 진단 변천사 (4번 갈렸음)

1. **첫 가설** (issue_koalpaca_Q.md): 양자화 mismatch (NF4↔K-quants). → Path A로 NF4 정확 재현해도 실패 → **부분 기각**.

2. **두 번째**: LoRA 학습 부족 (epoch=0.39, loss=2.53). → 모델 공식 F-1 60.94% = 학습 환경에선 작동. → 재학습은 답 아님.

3. **세 번째**: 1070 Ti CPU offload가 LoRA 효과 손실. → llama.cpp 전부 GPU에서도 동일 실패 → **부분 기각**.

4. **네 번째** (잘못된 결론): "LoRA가 환경에 fragile, 완전 재현 불가능." → Modal에서도 1500자 입력으론 실패 후 임시 결론.

5. **최종 진단** (xlsx 입수 후): **입력 포맷이 학습 분포와 어긋났음.** 결정적 차이:
   - **발화자 구분자**: 우리 = `발화자 : ` (콜론) / 학습 = `발화자\t` (**탭**)
   - **비식별화**: 우리 = raw text / 학습 = `@NAME @AGE @PLACE @COMPANY @TITLE @DATE` 등 마커 적용된 상태
   - **입력 길이**: 우리 = 1500자 / 학습 분포 median = **22,872자**
   - 3000자에서도 0/4, **5000자부터 partial pass (2/4)**, 9000자도 2/4

Modal A10G 환경 + 위 3가지 동시 만족 시 안정적 partial pass. AI Hub F-1 60% 환경 90% 재현.

## 부수 발견 (로컬 디버깅 중 알게 된 것들)

- **transformers 5.x는 Windows에서 12.8B sharded safetensors 로드 시 access violation으로 세그폴트** (`torch/storage.py:456`). 4.x로 다운그레이드 필요.
- **peft 0.12는 어댑터의 `eva_config` 필드 모름** → 0.14 이상 필요.
- **GPT-NeoX tokenizer가 `token_type_ids` 반환** → `generate()` 거부, pop 또는 `return_token_type_ids=False`.
- **bitsandbytes NF4 + CPU offload는 `llm_int8_enable_fp32_cpu_offload=True` 명시 필요** (명세서 누락).
- **C: 드라이브 4.3GB만 남아 pip/HF 캐시 E:로 우회 필요** (디스크 공간 함정).
- **tokenizer는 adapter 폴더(`koalpaca_save/`)에서 로드**해야 함 (`<|sep|>`, `<|acc|>`, `<|tel|>`, `<|rrn|>` 등 special tokens 포함). 베이스 모델 토크나이저는 일부 누락 가능.
- **PowerShell 5.1 + Modal CLI = cp949 인코딩 에러** (✓ 이모지). `PYTHONUTF8=1 modal deploy ...`로 우회.

## 진짜 원인 한 줄

**모델은 멀쩡했다. 우리가 학습 분포와 다른 포맷·길이·비식별화 입력을 줘서 모델이 평소 "상담사" 캐릭터로 돌아가 대화를 이어 썼던 것.**

해결책: 입력에 (a) 탭 구분, (b) `@NAME` 류 비식별화, (c) 5000자 이상 보장만 하면 partial pass 달성. 이 처리는 `src/summarizer.py`의 `_normalize_transcript` + `_MIN_INPUT_CHARS=5000` 가드가 담당.
